# `data/` 目录使用规则

> 本文件定义本地数据目录 `data/` 的子目录划分与使用规则，供 AI 代理与维护者执行。首次建立：2026-10-10。`data/` 整体被 `.gitignore` 忽略，任何真实影像**不进入 Git**（依据 `AGENTS.md` 第 4 节）。

## 1. 通用规则

1. **按类型分目录存放**，不得混放；新类型出现时先在本文件登记子目录用途，再存放文件。
2. **外部获取的每个文件必须在 `docs/model_provenance.md` 或相应清单中登记**：来源、大小、SHA-256、与来源的一致性核验结果；下载后应立即用 `git hash-object` 与来源平台（如 GitHub Contents API）的 blob 哈希比对。
3. `data/` 下的文件**默认不删除、不覆盖、不改名**；调整位置时须同步更新清单中的本地路径并追加变更历史。
4. 用于正式独立评估的数据集（`raw/`）还需满足 `AGENTS.md` 第 7.1 节的记录要求：样本ID、气旋ID、图像UTC时间、标签时间/机构/定义、来源与处理版本，并评估与上游训练样本的重叠风险。
5. 空目录不代表数据已就绪；引用数据前先确认实际文件与清单一致。

## 2. 子目录定义

| 子目录 | 用途 | 存放内容 | 禁止内容 |
| --- | --- | --- | --- |
| `samples/` | 上游或第三方提供的**模型输入示例图** | 与模型输入契约对应的示例图像（现含上游 `example_image.jpg`） | 结果图表、评估输出、非输入用途文件 |
| `reference/` | 上游或第三方提供的**参考材料**（非模型输入） | 作者自报的验证结果图、对比图表等（现含上游 `valid_test.png`） | 任何会被送入模型推理的图像 |
| `raw/` | 本项目独立评估用的**原始卫星图像**（预留） | 未做本项目预处理的原始影像及其原始标注 | 预处理后的图像、临时实验中间产物 |
| `processed/` | 本项目**预处理后**的图像（预留） | 经本项目预处理管线生成、供推理/评估使用的图像及其元数据 | 无法追溯到 `raw/` 来源与处理版本的文件 |

## 3. 预留目录的启用规则

- `raw/`、`processed/` 启用时须同时登记：数据来源与许可、获取日期、目录内文件命名规则、与 `docs/model_provenance.md`（外部权重/示例）或新建数据清单的对应关系。
- 评估数据按完整气旋个例组织时，目录结构（如按 `raw/<basin>/<storm_id>/`）在启用时一并确定并记入本文件。
